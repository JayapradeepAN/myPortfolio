Key problems identified

Navigation

No persistent progress visibility

Users couldn't gauge how far through the workflow they were or jump to a previously completed step without losing all subsequent data.

Error prevention

Mutually exclusive features without warning

Enabling Email Printing and Secure Printing simultaneously caused silent failures. No constraint feedback was surfaced until post-submission.

Cognitive load

Buried contextual help

Technical fields like "Server" had no inline guidance. Admins had to open external documentation mid-task, breaking flow and causing errors.

Data confidence

No pre-submission summary

The workflow moved directly to creation without a confirmation step. There was no way to review all settings together before committing changes.

Flexibility

Linear forced sequence

Expert users with well-known configurations still had to step through every screen in order. The system did not accommodate experienced, efficient patterns.

Inline testing

Email setup required external verification

After entering mail server details, admins had to send a test email externally to validate the configuration - a round-trip that caused significant delays.

04 - Design Decisions

Screen-by-screen breakdown

Each screen in the redesigned workflow addresses a specific research-backed pain point. Here I annotate the key design decisions and their rationale.

Step 1 of 10 - General information

Type selector & inline contextual help

The original form had no type selection - users had to know whether to create a Physical or WalkUp printer before starting. The redesign surfaces this as the first choice with clear radio buttons, giving immediate context.

The Server field gained a tooltip (ⓘ) explaining DNS vs IP address with a concrete example - directly addressing the #3 pain point from the survey. The tooltip is accessible via hover and keyboard focus.

Error prevention Contextual help Progressive disclosure
Step 2 of 10 - Container

Split-pane tree navigation with item grid

The legacy flow displayed containers in a flat list, making it impossible to understand the organisational hierarchy. The redesign introduced a split-pane layout: a collapsible directory tree on the left, and a content grid on the right that responds to the selected folder.

This mirrors the mental model of file system navigation - a pattern all IT admins know. The selected item count badge at the top provides at-a-glance confirmation, and checkmarks persist as users browse.

Mental model match Familiar pattern State persistence
Step 3 of 10 - Print manager

Active-only filtering with contextual notice

Research revealed that admins were frequently confused when inactive print managers appeared in the list and selected them, causing invisible failures. The redesign filters to active managers only, surfacing a persistent blue notice banner explaining this constraint.

This single change - informed by direct observation during contextual inquiry - was projected to prevent approximately 31% of post-creation error reports related to print manager issues.

Constrained choice Transparent filtering Error prevention
Step 5 of 10 - Features

Real-time conflict warnings

The most impactful design decision in the entire workflow. The legacy system allowed mutually exclusive features (e.g. Auditing + Direct Printing, Email Printing + Secure Printing) to be enabled simultaneously, with errors only surfacing after printer creation.

The redesign uses a persistent yellow warning panel that appears as soon as a conflicting combination is detected, listing the specific constraint in plain language. Toggles are visually grouped by category (End user, Administrative, Job holds) to reinforce the conceptual structure.

Real-time validation Constraint transparency Grouped information
Step 7 of 10 - Email configuration

Inline mail testing eliminates round-trips

Previously, admins entered mail server credentials and could only verify them by sending a test email from an external client and waiting. This took an average of 4 additional minutes per printer and was the top source of setup abandonment.

The redesigned step includes a "Test mail" button that validates the SMTP/IMAP connection inline. A green checkmark appears on success, and the Next button is only enabled after a successful test - ensuring valid configuration before proceeding.

Inline validation Confidence building Gate-based progression
Step 8 of 10 - LPR configuration

Inline CRUD with typed entry dropdown

The legacy LPR configuration was a static list with no ability to add, modify, or delete entries within the workflow. Admins had to exit and return to a separate settings screen.

The redesign introduces inline add/edit/delete within the wizard step. The add row uses a type-selector dropdown (IP address, IP address range, Subnet) that dynamically changes the input fields - reducing invalid entries by 44% in UAT.

Inline editing Context-sensitive inputs Reduced context switching
Step 10 of 10 - Summary

Full review before commitment

The final screen was completely absent in the legacy flow. The Summary step presents every configured value in a scannable list grouped by section. All completed steps appear with green checkmarks in the sidebar, giving users confidence before pressing Finish.

The "Go to summary" shortcut (available from any step after Drivers) allows expert users to jump ahead and review the defaults - a key efficiency feature for admins who create many similar printers.

Pre-commit review Expert shortcut Confidence building

Core design decisions

The six highest-leverage design choices that drove outcome improvements.

🧭

Persistent sidebar navigator

A fixed left-rail stepper showing all steps with completion status (green checkmarks, blue active dot) replaced the invisible linear progression. Users can click any completed step to revisit it.

Heuristic: Visibility of system status + User control and freedom
⚡

"Go to summary" expert path

After completing Drivers, a secondary button appears alongside Next. Power users can skip to the final review, relying on defaults for remaining steps - supporting both novice and expert flows.

Heuristic: Flexibility and efficiency of use
ℹ️

Contextual tooltips on technical fields

Fields with non-obvious expectations (Server, Network identifier) gained ⓘ icons with hover/focus tooltips. Copy was written with concrete examples (e.g. "print.mycompany.com or 129.63.47.78").

Heuristic: Help and documentation + Error prevention
⚠️

Real-time feature conflict warnings

A non-blocking yellow callout lists specific incompatible pairs as they are toggled. The warning uses plain language ("Auditing and Direct printing can't be enabled at the same time") not error codes.

Heuristic: Error prevention + Help users recognise errors
✉️

Inline email connectivity test

A "Test mail" button validates SMTP/IMAP credentials without leaving the screen. The Next button is gated on test success, preventing invalid configurations from propagating to printer creation.

Heuristic: Error prevention + Match system and real world
📋

Pre-commit summary review

A full read-only summary of every configured attribute is presented on the final step, with Back navigation available. Admins can scan the complete configuration before pressing Finish for the first time.

Heuristic: Error prevention + Recognition over recall
05 - Evaluation

Nielsen heuristics applied

I evaluated both the legacy and redesigned flows against Nielsen's 10 usability heuristics to ensure systematic coverage of all usability dimensions.

01

Visibility of system status

Sidebar stepper shows step completion state at all times. Active step is highlighted, completed steps marked with checkmarks.

02

Match system & real world

Container navigation mirrors file-system tree metaphor. Printer type labels use hardware terminology familiar to IT admins.

03

User control & freedom

Non-linear navigation via sidebar. Back buttons on every screen. X button to dismiss the modal without losing dashboard context.

04

Consistency & standards

Follows the OES design system. Button placement, form patterns, and modal behaviour are consistent across all workflow steps.

05

Error prevention

Active-manager filtering, feature conflict warnings, email test gate, and required field validation all prevent errors before they occur.

06

Recognition over recall

Summary screen shows all settings together. Selected items in Container/Print Manager use checkmarks rather than requiring users to remember selections.

07

Flexibility & efficiency

"Go to summary" shortcut for expert users. Tag autocomplete and paginated tables with search reduce time-on-task for repeat configurations.

08

Aesthetic & minimalist design

Each step shows only relevant fields. Progressive disclosure surfaces sub-steps (Email config, LPR config) only when parent features are enabled.

09

Recognise & recover from errors

Feature conflict warnings use plain language. Email test failure surfaces actionable next steps. Inline validation highlights the specific field in error.

10

Help & documentation

Contextual tooltips on technical fields. Example values in placeholder text. An accessible "View tutorial" link persists in the dashboard header.

07 - Reflection

What I learned & what's next

Every project leaves behind lessons worth capturing - both the things that went well and the constraints that shaped what wasn't possible in this release.

Lessons learned

  • Contextual inquiry was essential. Watching admins work revealed the "invisible" workarounds that surveys and interviews never surface - like maintaining personal spreadsheets of common IP addresses.
  • Progressive disclosure of sub-steps (Email config, LPR config) only when relevant features are enabled dramatically reduced perceived complexity. But it must be signalled in advance - not revealed mid-flow as a surprise.
  • The inline "Test mail" feature had the highest per-effort ROI of any design decision - one button eliminated the most time-consuming failure mode entirely.
  • Engineering partnership early (week 3) prevented three design directions that weren't technically feasible within the sprint. I should have involved them sooner in discovery, not just ideation.
  • The "Go to summary" expert shortcut was the most requested feature in the post-launch survey. Next time, I'd test the button label and visual prominence earlier rather than iterating on it late.

Future opportunities

  • Printer templates - allow admins to save a completed configuration as a reusable template for deploying identical printers at scale, directly addressing the #1 unmet need surfaced post-launch.
  • Bulk create - extend the workflow to support creating multiple printers from a CSV import, targeting the onboarding of new office floors where 50+ printers may need setup in one session.
  • AI-assisted suggestions - surface print manager and driver recommendations based on location and printer model to reduce decision fatigue for infrequent admins like Sarah.
  • Mobile admin - the workflow's modal format is not optimised for tablet-based field technicians; a responsive overhaul is planned for release 24.1.
  • Analytics integration - track which steps have the highest "Back" rate in production to identify remaining friction points for continuous improvement without needing another full research cycle.
